# Engineering

## Toolchain and workspace

- Rust 1.99.1 pinned in `rust-toolchain.toml`, edition 2024, resolver 3. No nightly in
  shipped code. Update the pin in its own commit and run the full checks.
- The root `Cargo.toml` owns versions and internal paths. Members use `workspace = true`
  for dependencies, lints and package metadata, and enable optional features only where
  consumed. `Cargo.lock` is generated by cargo, committed, and used with `--locked`.
  The root lists its internal packages by layer and its external ones by purpose (math, data,
  formats, graphics, audio, video, localization, verification); an entry nothing uses is kept as a
  comment under "Candidates" until a crate needs it. `scripts/tests/test_manifests.py` checks
  all of this: every crate is a member and listed by layer, no member names a version or path,
  every dependency is declared once in the root, and nothing declared is unused.
- Executables live in `apps/`; reusable libraries live in `crates/<layer>/` where the layer is
  `foundation`, `editing`, `io`, `adapters`, `services` or `presentation` (see ARCHITECTURE.md).
  Do not add a crate until it has code and tests.
- Rust files stay under 500 lines unless splitting would make them worse. Tests live in their
  own files next to the code (`tests.rs`, or a `tests/` directory split by topic), and a type's
  behaviour is split into modules by topic rather than grown in one file.
- `original/` is a read-only archive of the pre-rewrite code. It is excluded from the
  workspace and must never become a build dependency, symlink, `include!` or copied tree.
  Code adapted from it needs recorded provenance (source path, license, changes, tests).
  Do not claim clean-room provenance for translated code. By the maintainer's decision, text and
  data tables from it (translations, shortcut tables) may be converted into Flare's formats, with
  the provenance recorded under "Third-party format references used" below. No C++ code is pasted.
- `third_party/` holds pinned submodules (today `ruffle`), also excluded from the workspace. Their
  source is used unmodified under their licences and only through a path dependency behind a
  feature that is off by default (`flare-ruffle`'s `render-check`); CI and release checkouts fetch
  them because cargo reads their manifests. Moving the pin is a commit of its own. The `swf` crate that
  publishing uses is the submodule's, so every build needs the checkout, and a `[patch.crates-io]`
  entry makes Ruffle's own dependencies use that copy too: one `swf` in the build.
- `experiments/` holds isolated experiments with their own lockfiles; they are never part
  of the product dependency graph.

## Code conventions

- Typed errors in libraries (`thiserror`), `anyhow` only at application boundaries.
- Safe foundational crates `#![forbid(unsafe_code)]`. No public safe API may rely on callers
  upholding raw-pointer validity.
- No `unwrap`, `expect`, panics or unchecked casts on user data or routine errors. Test
  modules may allow `clippy::expect_used`.
- No GUI, GPU, database, async runtime or OS objects in document and geometry semantics.
- Document coordinates are finite `f64`; convert explicitly at rendering boundaries.
- Everything that grows is bounded: history depth, recursion depth, node counts, file and
  payload sizes, image sizes.
- Only validated edit transactions mutate documents; a failed batch changes nothing.

## Performance

See [PERFORMANCE.md](PERFORMANCE.md) for the rules (measure first, nothing slow on the UI thread,
share rather than copy, draw only what is visible, bound everything, drop stale results) and
the measurements behind them. New features follow them.

## Verification

Before committing:

```
cargo fmt --all --check
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo test --workspace --locked
```

The tests that need a GPU adapter (Ruffle playing and drawing our movies) are `#[ignore]`d there,
because a machine without a GPU would fail them, and CI does not run them. Run
`scripts/gpu_tests.sh` on a machine with a GPU before changing the player, or what we publish
for it, and report its result. `scripts/gui_tests.sh` runs the real desktop app on timers (an `autotest` build): Test Movie opens in a window of its own, that window closes, and the editor keeps drawing until it quits; it needs a display and a GPU and must pass before a change to the windows or the player.

Add a regression test before or with a behaviour fix. Test malformed input, save failures,
cancellation and resource limits. Do not update expected outputs to make a failure disappear.
A skipped test is skipped, not passed. Report status truthfully: a signature check is not a
parser, a parser is not an editor, and an untested capability is not supported.

### Fault injection and invariants

Beyond example-based tests there are randomized, seeded checks (so failures reproduce):
corrupted and truncated project files must never panic and are usually refused, and long
random edit sequences must never produce an invalid document, never change anything on a
rejected batch, and undo back to the exact starting document. When adding a new edit,
make sure these cover it. Check that a new invariant test can fail: temporarily break the
code it protects and confirm the test notices.

## Continuous integration

Workflows are in `.github/workflows/`; the toolchain, cache and Linux libraries are set up once
in `.github/actions/setup-rust`. Every workflow except `nightly.yml` (a daily schedule, and by hand) and `platforms.yml` (called by `release.yml` and `nightly.yml`) runs on pushes to `main`, on pull requests and by
hand (`workflow_dispatch`), cancels a superseded run of the same branch or pull request (never on `main`), and has read-only
`contents` permission unless a job says otherwise.

| Workflow | What it does | Target |
| --- | --- | --- |
| `ci.yml` | fmt (Linux only), clippy and tests on Linux, Windows and macOS; scripts tests, wasm checks, `cargo audit`, file-length and docs rules | Linux, Windows, macOS, Web |
| `android.yml` | universal, arm64-v8a and x86_64 APKs with `cargo apk` (ChromeOS runs the x86_64 or arm64 one; the manifest makes touch, keyboard, mouse and camera optional and the window resizable) | Android |
| `ios.yml` | compiles `flare-shell` and the desktop binary for `aarch64-apple-ios` (window-system and clipboard crates are gated off iOS in `flare-shell`'s Cargo.toml, and rfd is gated off iOS in `flare-platform`'s), then wraps the binary in an experimental unsigned `.ipa`. This is a build check, not an iOS app; see SURFACES.md | iOS (not yet an app) |
| `pages.yml` | builds the page with `apps/flare-web/scripts/build.sh`; a push to `main` deploys it to GitHub Pages | Web |
| `release.yml` | on a `v*` tag: portable archives, MSI, DMG, AppImage, deb, rpm and Flatpak for Windows, macOS and Linux (x86_64 and arm64), checksums, GitHub release | Windows, macOS, Linux |
| `platforms.yml` | reusable (called, no triggers of its own): the desktop, command line and MCP packages for every target, each built natively; used by `release.yml` and `nightly.yml` | Windows, macOS, Linux |
| `nightly.yml` | a daily build of `main` when it has new commits, and by hand: the platform packages, Android APKs and browser build, published to the rolling `nightly` pre-release (never a `v*` tag, so `release.yml` does not run) | Windows, macOS, Linux, Android, Web |

FreeBSD is not built: its workflow built a path that no longer exists and always reported success.
Add it back as a non-blocking job when a maintainer wants it.

Owner-only settings and secrets (no workflow can set these): Settings > Pages > Source "GitHub
Actions"; a Play upload keystore, Apple signing identity and Windows code-signing certificate
as repository secrets when signed builds are wanted.

## Code map for tools and newcomers

[codesight](https://www.npmjs.com/package/codesight) scans the repository and writes `.codesight/`: a
short map of the crates, the document schema, the libraries and the events, so a person or an AI
tool can find their way without reading every file. It is generated, never committed (`.codesight`
is in `.gitignore`) and out of date as soon as the code moves. Keep it current while working with

```
npx codesight --wiki --watch
```

which also writes a wiki and rescans when files change. It is a reading aid: the code, the tests and
these docs are the source of truth, and nothing in the build depends on it.

## Commits

Small conventional commits: `feat(scope)`, `fix(scope)`, `refactor(scope)`, `test(scope)`,
`docs(scope)`, `build(scope)`, `perf(scope)`, `chore(scope)`. One coherent concern per
commit, with compatibility or provenance notes in the body when relevant. Never commit
credentials or proprietary reference projects.

## Game references

The game world (`flare-game`) was ported from Flare's own archived C++ scaffold (`original/`). Two
references were read for architecture only, and no code was copied from either: Citrus Engine
(https://github.com/DaVikingCode/Citrus-Engine, MIT) and Adobe Flash Simple Game Engine
(https://github.com/benjamin-stern/Adobe-Flash--Simple-Game-Engine). The second repository's licence
could not be read from this environment, so nothing from it may be ported until it is checked.

  Apache-2.0). Its origin and the licence's text are in `packaging/MODEL_LICENSES.txt`, which every
  package carries beside the font licences. Not code: the weights are data the runtime reads.

- OpenToonz (BSD-3-Clause, Copyright (c) DWANGO Co., Ltd. and contributors; LICENSE.txt in
  https://github.com/opentoonz/opentoonz): the PLI tag layout, dynamic-width integers, thick
  quadratic chain decoding and the style/colour tags in `crates/io/flare-toonz/src/pli.rs` are
  ported from `toonz/sources/image/pli/pli_io.cpp` and `tiio_pli.cpp`; the palette style text of
  `.tpl` files follows `common/tvrender/tcolorstyles.cpp`. The BSD notice is: redistributions of
  source keep the copyright notice, the conditions and the disclaimer; the names of the
  contributors are not used to endorse derived products. Tahoma2D carries the same licence and
  was only compared.
- OpenToonz interface translations (BSD-3-Clause, as above), converted into `localizations/ru`,
  `localizations/cs` and `localizations/it`. Each message whose English source text is also a
  source in `original/flare/sources/translations/{russian,czech,italian}/*.ts` with a finished
  translation takes that translation as it is (Russian 178 messages, Czech 170, Italian 114). Its
  text was not re-checked for Flare's context, so a word can fit OpenToonz better than Flare; for
  example the Czech Stage reads "Fáze". Every other message (Russian 679, Czech 687, Italian 743) was
  written from Flare's English and is a machine translation by Claude. None of them has yet been
  reviewed by a native speaker; that review is open. The three READMEs in `docs/translations/` are
  machine translations too. Only the matched messages were copied out of the `.ts` files; the files themselves are not copied.
- OpenToonz stroke styles (BSD-3-Clause, as above): the names and the idea of Herringbone, Rope and
  Zigzag come from its stroke style sources (`flare/sources/colorfx/strokestyles.cpp`,
  `zigzagstyles.cpp`). No code was copied: the geometry is written fresh in
  `crates/services/flare-render/src/pattern.rs`, and Hatched and Ragged are Flare's own.
- jpdurigan/godot_moho_importer (MIT, Copyright (c) 2022 Joao Pedro Durigan): the Moho mesh
  layout (`mesh.points`, `mesh.curves`) and the `anim_pos`, `anim_angle`, `anim_scale` track names
  used by `crates/io/flare-moho`.
- flipnote.js (`jaames/flipnote.js`, MIT, Copyright (c) 2018 James Daniel; LICENSE in the
  repository): the Flipnote Studio PPM reader in `crates/io/flare-import/src/flipnote/` follows
  `src/parsers/PpmParser.ts` for the header and metadata offsets, the frame line types, the XOR and
  translation rule, the palette bits, the frame rate table and the IMA ADPCM decoder. The Rust is
  written from that reading, not copied line by line; the notice above applies to the ported logic.
  The KWZ parser was read but nothing from it is used yet. See docs/FLIPNOTE.md.
- lifeart/fla-viewer (`lifeart/fla-viewer`, ISC per `package.json`; no LICENSE file): its
  `src/motion-object.ts` was read for the meaning of the motion object fields (ticks, anchor and
  handle pairs, which channels are offsets and which are absolute). Behaviour reference only, no
  code taken. `crates/io/flare-import/src/xfl/motion/` is written from that description and from
  Flare's own tests (`tests/xfl_motion.rs`).
- Clip Studio Paint brush behaviour (Celsys; proprietary, no licence for its code): a written report
  of a static analysis of version 1.11.8's default tool database and of two older, unprotected Celsys
  libraries shipped with it, given to the project by the maintainer. Ideas and a few numbers only:
  the stabilizer as an average of the last N samples whose window shortens on fast moves
  (`crates/foundation/flare-input/src/stabilizer.rs`), the taper as a quarter-sine ease of pressure
  (`crates/editing/flare-tools/src/brush/stroke.rs`), and the pressure curve points and stabilizer
  levels of four inking pens as starting values for Flare's G-pen, Mapping pen, Turnip pen and Brush
  pen profiles. No code, tip images, textures or database files were copied, and the Rust is written
  fresh. Blur and Smudge (`crates/editing/flare-tools/src/blend/`) follow the report's description
  of the dab engine: dabs spaced by a fraction of their size with the remainder carried on, the
  one-pixel distance ramp and the clipped Gaussian for a dab's edge, the rules for dabs under four
  pixels, a per-stroke coverage capped at the stroke's strength over a copy of the bitmap from
  before the stroke, blurring towards a blurred copy, and the smudged color as a running average of
  what is under the brush (`5 / (stretch + 5)`), and the default sizes, hardness and stretch of the
  Blur and Finger tip tools. The blur itself (three box blurs) and the tiling are Flare's own. Paper
  texture, dual brushes and painting with color are not used: Flare has no raster brush yet
  (BACKLOG WP-11).
- i_overlay and its `i_float`, `i_shape`, `i_tree`, `i_key_sort` crates (MIT OR Apache-2.0, linked as a dependency, no code copied): the polygon booleans the Eraser cuts with.
- usvg and its parser crates (MIT/Apache-2.0, linked as a dependency, no code copied): the SVG reader of `crates/io/flare-import/src/svg.rs`, with its text feature off.
- SimplSam/moho-bvh-bones (CC BY-NC-SA 4.0): not used; nothing was copied or ported.
- Bauxitedev/bitmapflow (optical-flow frame interpolation for pixel art): the repository has no

- ShuhongChen/eisai-anime-interpolator (anime inbetweening, SoftSplat forward warping, distance
